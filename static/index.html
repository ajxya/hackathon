How EDFlow Works

        

          EDFlow is a rules-based decision-support demo for emergency
          department surge management. Nothing here is a real clinical
          tool — every patient, injury, and nearby facility is synthetic,
          and every recommendation comes from simple, transparent
          thresholds, not a machine-learning model.
        


        
Priority tiers and wait-time targets

        

          Every patient is assigned a priority tier on arrival. The waiting
          queue is always served in tier order — Tier 1 first — regardless
          of who arrived first.
        

        

          
            
TierMeaningTarget wait

          
          
            
Tier 1Immediately life-threateningImmediate

            
Tier 2Emergent10 min

            
Tier 3Urgent30 min

            
Tier 4Less urgent60 min

            
Tier 5Non-urgent120 min

          
        


        
The escalation ladder

        

          When a Tier 1–2 patient is past their target, EDFlow escalates
          through four rungs, in order, only moving to the next one if the
          current one can't fully restore targets:
        

        
    
          
  1. The ED's own resources — if there's no breach yet, normal discharge turnover is trusted to keep up on its own.
    2. 
          
  2. Hospital float pool — pull nurses, physicians, or rooms already available elsewhere in the hospital.
    3. 
          
  3. Overflow capacity — stand up extra physical beds within the ED.
    4. 
          
  4. Relocation — redirect lower-tier patients to a nearby facility.
    5. 
        

        

          Every recommended quantity is capped at what's actually
          available — EDFlow will never recommend more nurses, rooms, or
          beds than the reserve it's drawing from actually has.
        


        
Relocation rules

        
    
          
  • Tier 1 patients are never relocated.
    • 
          
  • Lower-tier ambulance arrivals (Tiers 3–5) are relocated first.
    • 
          
  • Destinations are chosen by capability match, then estimated wait for that patient's tier.
    • 
          
  • EDFlow never relocates a patient to a facility that is currently red.
    • 
          
  • Relocation only ever happens with explicit user approval — nothing here is automatic.
    • 
        


        
Simulated data

        

          All patients, injuries, and nearby-facility data (hospitals and
          urgent care sites) are entirely synthetic and randomly generated.
          Nearby facilities run their own simplified simulation that drifts
          independently over time, so they don't all change together.
          Nothing in EDFlow reflects a real hospital, real patients, or
          real capacity. The recommendation engine above is, and remains,
          entirely rules-based — there is no machine-learning model behind
          it anywhere in EDFlow.
        


        
Situation report

        

          The "Generate situation report" button on the Impact tab builds
          a shift-handoff report from a fixed, deterministic template —
          not an AI model. It reads the same session data the rest of the
          dashboard is built from, so it always works instantly, offline,
          and can never disagree with what's on screen.
        


        
EDFlow Assistant

        

          The chat button in the bottom-right corner is a small AI-backed
          assistant that explains the current simulated state and the
          rules-based recommendations shown above, and can answer
          questions or summarize recent activity. It only explains and
          answers questions — it never makes a decision or takes an
          action itself; every real change still requires the user to
          click "Apply" in the dashboard. It also only ever gives
          operational information (capacity, staffing, wait times), never
          medical, diagnostic, or treatment advice, and every answer is
          about this simulated dashboard, not a real patient or hospital.
