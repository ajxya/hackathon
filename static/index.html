How EDFlow Works

EDFlow is a rules-based decision-support demo for emergency department surge management. Nothing here is a real clinical tool — every patient, injury, and nearby facility is synthetic, and every recommendation comes from simple, transparent thresholds, not a machine-learning model.

The simulated clock

EDFlow runs on a compressed clock: 1 real second = 1 simulated minute. Every wait time, length of stay, and target on this page is stated in that simulated time — a "10 minute target" plays out over 10 real seconds. This is also what makes a 30-second demo surge represent a realistic half-hour of ED activity.

Priority tiers and wait-time targets

Every patient is assigned a priority tier on arrival. The waiting queue is always served in tier order — Tier 1 first — regardless of who arrived first.

TierMeaningTarget wait
T1Immediately life-threateningImmediate
T2Emergent10 min
T3Urgent30 min
T4Less urgent60 min
T5Non-urgent120 min

The escalation ladder

When a Tier 1–2 patient is past their target — or one is projected to be soon (see below) — EDFlow escalates through four rungs, in order, only moving to the next one if the current one can't fully restore targets:

  1. The ED's own resources — if there's no breach yet and none is imminent, normal discharge turnover is trusted to keep up on its own.
  2. Hospital float pool — pull nurses, physicians, or rooms already available elsewhere in the hospital.
  3. Overflow capacity — stand up extra physical beds within the ED.
  4. Relocation — redirect lower-tier patients to a nearby facility.

Every recommended quantity is need-based: it's sized from current load against realistic per-nurse, per-physician, and per-room ratios, then capped at what's actually available — EDFlow will never recommend more nurses, rooms, or beds than the reserve it's drawing from actually has.

Proactive breach projection

EDFlow doesn't only react after a Tier 1–2 patient has already missed their target — it also watches how fast beds are filling and projects when they'll run out entirely, which is the moment the next Tier 1–2 arrival would breach (Tier 1's target is immediate; Tier 2's is 10 minutes). When that projected breach is close enough, the recommendation card shows it directly (for example, "Tier 1-2 breach projected in ~6 min") and the ladder starts recommending float pool or overflow capacity before the breach actually happens, not after.

Left without being seen

Lower-tier patients (Tiers 3–5) don't wait forever: if a patient's wait passes twice their tier's target, they leave without being seen. This is logged in the event log and counted on the dashboard, and it's also what naturally caps how long a low-tier wait can climb during a heavy surge — Tier 1–2 patients are never eligible, since they're always served first.

Relocation rules

  • Tier 1 patients are never relocated.
  • Lower-tier ambulance arrivals (Tiers 3–5) are relocated first.
  • Destinations are chosen by capability match, then estimated wait for that patient's tier.
  • EDFlow never relocates a patient to a facility that is currently red.
  • Relocation only ever happens with explicit user approval — nothing here is automatic.

Simulated data

All patients, injuries, and nearby-facility data (hospitals and urgent care sites) are entirely synthetic and randomly generated. Nearby facilities run their own simplified simulation that drifts independently over time, so they don't all change together. Nothing in EDFlow reflects a real hospital, real patients, or real capacity. The recommendation engine above is, and remains, entirely rules-based — there is no machine-learning model behind it anywhere in EDFlow.

Situation report

The "Generate situation report" button on the Impact tab builds a shift-handoff report from a fixed, deterministic template — not an AI model. It reads the same session data the rest of the dashboard is built from, so it always works instantly, offline, and can never disagree with what's on screen.

EDFlow Assistant

The chat button in the bottom-right corner is a small AI-backed assistant that explains the current simulated state and the rules-based recommendations shown above, and can answer questions or summarize recent activity. It only explains and answers questions — it never makes a decision or takes an action itself; every real change still requires the user to click "Apply" in the dashboard. It also only ever gives operational information (capacity, staffing, wait times), never medical, diagnostic, or treatment advice, and every answer is about this simulated dashboard, not a real patient or hospital.

Impact of EDFlow (simulated comparison)

Behind the scenes, a second, parallel copy of this ED runs on the exact same arrivals — same patients, same tiers, same arrival times, same length of stay — but never gets a float nurse, an overflow bed, or a relocation. It represents this ED using only its own staff and beds. The Impact tab and situation report compare the two to show what EDFlow's recommendations actually changed. Both copies use the same discharge logic and the same wait-time formulas as the rest of the dashboard, so the numbers reconcile everywhere — but the comparison itself is entirely simulated: a shadow run of this same synthetic ED, not a real historical control group.
